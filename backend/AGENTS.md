# Backend agent instructions

Repository guidance for work on the Go backend.

## Build & Run Commands

```bash
make build        # compile to bin/maharych-api
make run          # go run ./src/cmd/server (starts on :8080)
make test         # go test ./...
make swagger      # regenerate Swagger docs (swag init -g src/cmd/server/main.go -o docs)
make tidy         # go mod tidy
make clean        # remove bin/
```

Swagger UI is served at `/swagger/index.html`. Regenerate docs after changing any `@` annotations in handler files.

## Architecture

Go module: `maharych-api` (Go 1.25.5). Framework: Gin. ORM: GORM with PostgreSQL.

Domain-grouped structure: each feature owns its handler, service, repository, and DTOs.

```
src/cmd/server/main.go    — entrypoint, DI wiring, router setup, Swagger annotations
src/internal/
  auth/                    — accounts, bcrypt, Google ID-token validation, JWT issuance
  interview/               — interview lifecycle (start, list, async end) and finalization events
    handler.go, service.go, commands.go, queries.go, repository.go, finisher.go, dto.go
  profile/                 — candidate profile and resume parsing
  feedback/                — feedback JSON and PDF proxy to the AI service
  broker/                  — RabbitMQ client (confirmed publish, reconnecting consumer)
  interviewoption/         — interview options (levels, positions, focuses)
    handler.go, service.go, repository.go, dto.go
  audio/                   — WebSocket audio streaming to AI service
    handler.go             — WS upgrade authenticated by a one-time ticket; ticket endpoint
    ticket.go              — single-use, 30 s WebSocket tickets
    bridge.go              — WebSocket ↔ gRPC relay (ping/pong, deadlines, session cap)
    dto.go
  health/                  — health check endpoint
  model/                   — shared GORM models (User, Interview, InterviewOption)
  middleware/              — auth, CORS, JWT parsing
  config/                  — env var loading
  database/                — DB connection (injected, no globals), migration, seed
  grpcclient/              — AI service gRPC client factory
  genproto/aiservicepb/    — generated protobuf code
docs/                      — generated by swag, do not edit manually
```

All API routes live under `/api/v1`. Swagger annotations use swaggo comment format on handler functions.

Dependencies are injected via constructors in `main.go` — no global state.

## Database

Connection configured via `DATABASE_URL` env var, or individual vars: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`. Defaults to `localhost:5432/maharych`.

Migrations run automatically on startup via `database.Migrate(db)` using GORM AutoMigrate.

## Conventions

- Each domain package follows handler → service → repository layering.
- Handlers parse HTTP, call services, map errors to status codes.
- Services contain business logic, return domain errors.
- Repositories encapsulate DB queries behind interfaces.
- Handlers return JSON via `c.JSON()`. Use `gin.H{}` for ad-hoc responses.
- Model fields use `json:"-"` to hide sensitive data (e.g. password hashes).
- The backend owns users, bcrypt, Google ID-token validation, JWT issuance, and users migrations. NextAuth owns the browser Google OAuth flow and web session. Google client secret is used only on the Next.js server; the backend requires the same `GOOGLE_CLIENT_ID` to verify ID-token audience.

## Interview finalization (asynchronous, via RabbitMQ)

`POST /interviews/{id}/end` does not wait for the AI. It sets status `finalizing`, publishes `interview.finish.requested` to exchange `maharych.events` (publisher confirms, mandatory) and answers `202`. voice_ai finalizes idempotently and publishes `interview.finished` `{interview_id, stage}`; `backend.interview.finished` consumes it (`interview.Commands.HandleFinished`) and stores `completed`/`abandoned`. Stage `failed` (retries exhausted) returns the interview to `in_progress`. Repeating `end` while `finalizing` re-publishes the request. Topology names are shared with `voice_ai_service/.../services/interview_events.py` and checked by its contract test. Set `RABBITMQ_URL`; without it ending interviews returns 503 instead of completing without the AI.

## Authentication contracts

`src/internal/auth/` handles `/api/v1/auth/{register,login,google}` directly in the API process. Success remains `{ user: { id, email }, token }`. JWTs use HS256 with string `sub`, `email`, `iat`, and a 24-hour `exp`. Tokens are validated with HS256 pinned and a required `exp`; `JWT_SECRET` must be at least 32 characters. The API JWT never appears in a URL: the browser calls `POST /interviews/{id}/audio-ticket` (authorized) and opens `/audio?ticket=...` with the returned single-use ticket. Preserve existing account IDs. Password hashes and Google subjects must never appear in responses or logs.

`database.Migrate` owns the existing `users` table and normalizes legacy empty Google subjects to NULL. Use an isolated database for migration checks. Google sign-in is disabled with HTTP 503 when `GOOGLE_CLIENT_ID` is empty; credentials login remains available.
